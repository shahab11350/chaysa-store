# گزارش آماده‌سازی پیش‌نمایش وردپرس چایسا — 2026-11-23

## دامنه و مجوز
- هدف: آماده‌سازی پیش‌نمایش غیرعملیاتی فروشگاه وردپرس/WooCommerce در مسیر `https://chaysa.ir/preview/`.
- دامنه اصلی و صفحه شمارش معکوس ریشه باید تا تأیید بصری مالک حفظ شوند.
- این مرحله صرفاً آماده‌سازی ابزار و پشتیبان‌گیری است؛ نصب وردپرس، ایجاد پایگاه داده، تغییر Nginx و فعال‌سازی فروش/پرداخت هنوز انجام نشده‌اند.
- پیش‌نمایش باید با Basic Authentication محافظت شود و سفارش/پرداخت واقعی نداشته باشد.

## وضعیت تأییدشده سرور
- Ubuntu 24.04.5 LTS؛ سرور `193.58.119.148`.
- Nginx فعال؛ `nginx -t` موفق.
- PHP-FPM 8.3 فعال؛ سوکت `/run/php/php8.3-fpm.sock` موجود.
- MariaDB فعال و روی `127.0.0.1:3306` گوش می‌دهد.
- BIND فعال؛ zone محلی `chaysa.ir` با `named-checkconf -z` و `named-checkzone` معتبر است.
- گواهی TLS دامنه‌های `chaysa.ir` و `www.chaysa.ir` تا 2027-02-20 معتبر گزارش شده است.
- UFW فعال؛ ورودی‌های 22/tcp، 80/tcp، 443/tcp و 53/tcp/udp مجاز هستند. پورت DNS در این مرحله تغییر نکرده است.
- فایل‌های شمارش معکوس `/var/www/html/index.html` و `chaysa-logo-option4.svg` پیش از هرگونه تغییر آتی موجود و دارای اندازه غیرصفر بودند.
- پاسخ HTTPS دامنه با resolve محلی HTTP 200 بوده؛ HTTP دامنه به HTTPS ریدایرکت می‌شود.
- در بررسی قبلی، وردپرس در `/var/www` نصب‌شده یافت نشد.

## نکات و محدودیت‌ها
- اجرای `wp --info` نسخه WP-CLI را تأیید کرد. فراخوانی `wp --version` در انتهای اسکریپت با هشدار ایمنی اجرای WP-CLI توسط root مواجه شد؛ این هشدار به‌تنهایی به معنی خرابی نصب نیست. برای فرمان‌های بعدی یا باید از کاربر سیستمی محدود استفاده شود یا در فرمان‌های مدیریتیِ ضروری گزینه `--allow-root` صریحاً اعمال شود.
- بسته‌های سیستم پیام دادند که kernel نصب‌شده مورد انتظار 6.8.0-149-generic است، در حالی که kernel جاری 6.8.0-147-generic است. راه‌اندازی مجدد انجام نشد؛ reboot نیازمند برنامه‌ریزی مستقل است.
- هیچ تغییری در محتوای سایت، فایل روزشمار، DNS، پایگاه داده، تنظیمات سایت Nginx یا انتشار Production انجام نشد.
- این گزارش، نصب وردپرس، WooCommerce، ایجاد دیتابیس، تنظیم احراز هویت پیش‌نمایش، آزمون مرورگر یا انتشار نهایی را ادعا نمی‌کند.

## نتیجه تلاش نخست برای نصب پیش‌نمایش — 2026-11-23

- اجرای اسکریپت نصب پس از عبور موفق از پیش‌پرواز، ایجاد موقت پایگاه داده و کاربر اختصاصی، و ایجاد مسیر پیش‌نمایش، در مرحله دریافت هسته وردپرس متوقف شد.
- خطای ثبت‌شده WP-CLI: `The requested locale (fa_IR) was not found.`؛ علت مستقیم، درخواست locale فارسی در فرمان `wp core download` بود. این خطا به‌تنهایی نشانه خرابی DNS، Nginx یا MariaDB نیست.
- سازوکار Rollback اسکریپت اجرا شد. ممیزی بعدی روی سرور تأیید کرد: مسیر `/var/www/html/preview` وجود ندارد؛ دیتابیس `chaysa_preview` و کاربر `chaysa_preview` وجود ندارند؛ قواعد `/preview/` در Nginx و فایل Basic Auth ایجاد نشده‌اند.
- هش‌های فایل‌های اصلی پس از Rollback با مقادیر قبل از نصب یکسان ماندند:
  - `index.html`: `412c64853c21110868181b89c9a9b54fa9d0756d708dfbf4d2d2f1e6301732a7`
  - `chaysa-logo-option4.svg`: `095e3463ed072236f1bd25b5ec82c17898e8b7b14758ef755c3025fbef48d80c`
- `nginx -t` پس از Rollback موفق بود. آزمون HTTPS ریشه سایت HTTP 200 و HTTP ریشه به HTTPS ریدایرکت 301 را نشان داد.
- وضعیت این تلاش: **نصب ناموفق و Rollback راستی‌آزمایی‌شده؛ هیچ پیش‌نمایش وردپرسی ایجاد نشده است.**
- اصلاح برنامه‌ریزی‌شده برای تلاش بعدی: دریافت هسته بدون `--locale=fa_IR`، سپس نصب بسته زبان فارسی و تغییر زبان سایت پس از نصب هسته. اجرای مجدد باید همچنان با کاربر سیستمی محدود، دیتابیس مستقل، Basic Auth، noindex و قفل کامل خرید/پرداخت انجام شود.
- هیچ تغییری در DNS، صفحه اصلی، منطق تجاری، سفارش/پرداخت Production یا انتشار Railway انجام نشده است. راه‌اندازی مجدد سرور نیز انجام نشده است.
